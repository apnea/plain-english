# plain-english

A testbed and recorded analysis for making LLM output (GLM models in particular) write plain, clear English, and for scoring any text against plain-English style rules.

Recorded 2026-11-23. Re-evaluation instructions at the bottom.

## The analysis

(plain-English style control for LLM output, plus deterministic scoring of any text):
**fit to task 30%, adoption/proof 20%, evidence of effectiveness 20%, maintenance 15%, maturity 15%**.

### Verdict

Ready-made tools win over a bespoke merged prompt. Adopted stack:

1. **agent-style** (generation-time rules + `review` CLI). Only candidate with a published,
   honest benchmark; contains the Orwell/Strunk/Pinker canon plus observed LLM failure
   modes (em-dash overuse, additive openers, summary closers, citation discipline).
   https://github.com/yzhao062/agent-style
2. **Vale** (scoring). Markup-aware prose linter; markdown handling avoids the
   line-per-sentence artifact described below. Packages: write-good, proselint, Readability.
   https://vale.sh
3. **proselint** (optional standalone scorer; usage/cliche checks complement write-good's
   passive/wordy checks). https://codeberg.org/amperser/proselint

Full notes with URLs: docs/research.md

## Testbed usage

```sh
vale <file.md>                       # deterministic scoring (0 errors = clean; warnings + suggestions)
.venv/bin/proselint check <file>     # usage/cliche checks (exit 1 if findings)
npx --yes agent-style@latest review <file>   # 21-rule audit with per-rule counts
node scripts/score.js <file>         # STE-style scorer (scripts/, from webSTE100)
```

The testbed was validated against ground truth: a synthetic GLM-style jargon paragraph
(`examples/slop.txt`) triggers 25 warnings + 55 suggestions in Vale and 6 violations in
`agent-style review`; the plain rewrite (`examples/plain.txt`) triggers 2 warnings + 12
informational suggestions and 0 violations. proselint is quiet on both (its checks are
usage-oriented; the canary `proselint check /tmp/x.txt` on "John is very unique and
utilizes this comprehensive methodology." fires 3 checks).

## The feedback loop

Vale only reports; the loop is you + a model:

```sh
# 1. get the repair prompt (fix list + fidelity rules + re-lint footer)
scripts/repair-prompt.sh doc.md > /tmp/prompt.txt
# 2. paste /tmp/prompt.txt together with the document text into any chatbot
# 3. save the rewritten text, re-lint, repeat until counts stop improving
vale doc-rewritten.md
scripts/repair-prompt.sh doc-rewritten.md
```

Options: `--max N` (fix lines shown, default 15), `--format md` (fenced block for
copy-paste), `--help`. Readability grade metrics collapse into one summary line;
informational polysyllable notes and the E-Prime rule are skipped. The script never
edits your file; the model does the rewriting, you stay in the loop.

## Known artifact: line-per-sentence linters

scripts/ste-checker.js (vendored from webSTE100) assumes one sentence per physical line.
On hard-wrapped prose it inflates paragraph counts ~3x and understates sentence length.
scripts/find-paras.mjs and scripts/find-issues.mjs implement corrected true-sentence
measurement. Vale is markup-aware and does not have this problem.
